# Design: Phase 13 — Integrations Expansion

## Context

Stripe, Twilio, and Spotify already have one-off hooks. There is no Integration Config DocType (payments_stripe looks it up and always misses), no sync log, no calendar/maps/DocuSign/QBO/Xero, and Apple/YouTube import throws a setup message. Tenant code must never `frappe.connect` another site. Secrets never log. Provider outages must not fail the surrounding workflow.

## Goals / Non-Goals

**Goals:** encrypted per-site credentials; webhook dedupe; calendar push/pull + iCal; geocode/travel-time; optional DocuSign; optional QBO/Xero; Apple + YouTube playlist import; owner Connections; degrade-to-skip.

**Non-Goals:** forking Stripe/Twilio into this module (they keep existing endpoints, but log via the same Sync Log when called); Metabase; multi-tenant shared Google org.

## Decisions

1. **One Integration Config row per provider on this site.** `provider` unique. `credentials` is a Frappe Password (JSON: tokens/keys). `settings` is non-secret JSON (calendar_id, realm_id). List APIs return `{provider, enabled, status, last_error}` only.

2. **Never fail the core write.** `observe.run(provider, action, fn)` catches, writes Sync Log `error`/`skipped`, returns `None`. Booking save, invoice submit, and native `send_contract` always succeed.

3. **HTTP client** `integrations/http.py` `request(method, url, headers, body, timeout=20)` strips `Authorization` from any error log. No third-party SDK required (urllib).

4. **Calendar.** On Event Booking `confirmed` / `canceled` / date change, enqueue `calendar.sync_booking`. Google Calendar API v3 and Graph `/me/events` using stored refresh tokens. Store `calendar_sync_id` on the booking. Inbound: hourly `calendar.pull` if connected; map external updates onto this site’s booking by sync id only. **iCal:** `GET /api/method/...ical_feed?token=` allow_guest; token hashed on Integration Config `ical`. Regenerated by owner.

5. **Maps.** `maps.geocode(address)` and `maps.travel_minutes(from_geo, to_geo)`. Provider from Config `mapbox` or `google_maps`, else env `EE_MAPBOX_TOKEN` / `EE_GOOGLE_MAPS_KEY`. Empty result if none. Venue save and quote travel use geocode when address has no geo. SPA never computes money; travel fee still comes from Service Area `flt`.

6. **DocuSign.** If Config `docusign` enabled, `send_contract` enqueues envelope create and still emails the native link as fallback. Webhook `envelope-completed` marks EE Contract `signed` only if native has not already signed (idempotent). No silent money.

7. **Accounting.** Sales Invoice `on_submit` and paid status enqueue `accounting.sync_invoice`. QBO and Xero REST; skip without tokens. Idempotent via last Sync Log `ok` for that invoice + provider.

8. **Streaming.** `music.fetch_playlist_tracks` also handles Apple Music (iTunes Lookup/Search, no secret) and YouTube (Data API if key on Config `youtube`, else skip with copy). Failures return empty import, not 500.

9. **Webhooks.** `api.integrations.inbound_webhook(provider)` allow_guest. Verify: Stripe already separate; DocuSign HMAC; Google channel token; generic `X-EE-Webhook-Token` vs Config. Dedupe Integration Webhook Event `provider`+`event_id`. Process in `frappe.enqueue`.

10. **UI.** `/owner/connections`. Copy: “Connections”, “Calendar”, “Maps”, “Signing”, “Books”, “Music”. No DocType names. Crew 403. Guests 403.

11. **Image** `0.0.69-ee` → `0.0.70-ee`.

## Risks

- [No OAuth client ids in cluster] → Connect buttons show setup copy; core product works.
- [Token refresh fails] → status=error on Config; next job skipped; owner sees last_error.
- [Calendar maps the wrong job] → only update rows whose `calendar_sync_id` matches; never take `tenant`/`site` args.
